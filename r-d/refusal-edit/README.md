# refusal-edit — a Claude Code mod that recovers from a refused prompt

When a turn ends because the model refused the prompt (Claude Code reports
`turn.complete` with `reason: "refusal"`), this mod says why and puts the
prompt back in the input box so it can be edited and resent. Written as a
mod (Claude Code plugin with function hooks) in October 2026, against Claude
Code 2.1.288; tests re-checked on 2.1.289.

## What it does

| `recovery` option | After a refusal |
|---|---|
| `rewind` (default) | Opens Claude Code's built-in rewind menu (`$.command.run({ command: "rewind" })`). The mod can't pick the message itself, so the toast says: press ↑ to pick your message, then Enter twice. Claude Code then cuts the conversation back and refills the box. In the transcript that becomes a new branch from the earlier message; the refused turn stays in the file as a dead branch. Falls back to `drop` if the menu can't be opened. |
| `drop` | Cuts the conversation itself, using compaction as the tool: calls `$.session.compact()`, and its own `session.compact` hook (trigger `plugin`) returns `e.messages.slice(0, i)`, everything before the refused prompt, with no summary. Compaction only works between turns, so it retries every 250 ms (up to ~10 s) while the refused turn is still closing. A `session.append` hook rewords the notice to "Refused message removed. Nothing was summarized." Then it puts the prompt back in the box (`$.prompt.fill`; appended below anything already typed). |
| `keep` | Only puts the prompt back in the box; the refused turn stays in the conversation. |

The reason is shown as a 12 s toast and logged (`$.ui.log`), because the rewind
menu covers the toast. Subagent refusals (`e.agentId` set) are ignored.

`/refusal-test [rewind|drop|keep]` runs the same recovery on your last prompt
with no real refusal, so every mode can be tried without tripping the classifier.

## Files

```
.claude-plugin/plugin.json   manifest + the `recovery` option (userConfig)
hooks/hooks.json             { "modules": ["./register.ts"] }
hooks/register.ts            the mod
tests/refusal-edit.test.ts   7 tests (claude plugin test)
```

`tsconfig.json` and `.claude-plugin/types/` are generated by Claude Code's
plugin tooling and are git-ignored.

## Reproduce

Needs Claude Code ≥ 2.1.287 (mods). From the repo root:

```bash
claude plugin validate r-d/refusal-edit
claude plugin test r-d/refusal-edit        # 7 pass

# a real, interactive window with the mod loaded (not -p: see below)
claude --plugin-dir r-d/refusal-edit
#   send any prompt, wait for the answer, then:
#   /refusal-test keep     → toast + your prompt back in the box
#   /refusal-test drop     → the last exchange disappears, prompt back in the box
#   /refusal-test rewind   → rewind menu opens; ↑ then Enter twice
```

To change the default mode: `/plugin` → refusal-edit → options, or pass it
per run as the `/refusal-test` argument.

If `claude plugin test` says hook modules are turned off ("the rollout switch
was saved off by an earlier session"), start `claude` once with network access
and run the tests again.

## Known gaps

- **The retry while the refused turn is closing is not tested.** The original
  test simulated "a turn is in flight" by throwing from a hook beneath the mod;
  the current test kit skips a throwing hook instead of passing the error up,
  so that can't be simulated any more. The test now checks the fallback (the
  compaction is refused → the prompt still goes back in the box). The exact
  error text the retry matches (`in flight`) has not been confirmed against a
  real engine.
- **The `drop` cut is only unit-tested.** In the test kit `$.session.compact()`
  arrives with no `trigger` and no messages, so the mod's cutting hook
  (matcher `trigger: "plugin"`) never runs there; `promptIndex`, which picks the
  cut, has its own test. The wiring needs an interactive check (above).
- **`-p` mode can't show recovery**: `claude -p "/refusal-test drop"` runs the
  command, but the process exits before the deferred recovery runs.
- **Effect on stored conversations** (`/voitta-store`): after `rewind` the
  refused turn stays in the transcript as a dead branch (kept byte for byte,
  not shown by the viewer, which follows the current branch). What Claude Code
  writes for a mod-made compaction (`drop`) hasn't been checked.
